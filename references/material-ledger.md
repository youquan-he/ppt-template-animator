# 素材台账与 brief

台账用于发现遗漏，不代替阅读和视觉核对。在工作目录保存 JSON、CSV 或 Markdown 均可。

## brief

记录目的、观众、场景、主题、一句话主张、时长/页数、语言、交付格式、必用内容、视觉气质、此前反馈。每项标记为 explicit（明确）、inferred（推断）或 unresolved（实质冲突或缺失）。说明影响设计的重要推断，无需让用户逐项批准可以合理确定的事项。

## 每条素材的字段

| 字段 | 含义 |
| --- | --- |
| material_id | 稳定编号，例如 M001 |
| source / locator | 文件路径或来源；PDF 页码、图号、表号、对话段落等 |
| role | 内容素材、设计/动画参考、背景资料 |
| requirement | 必须可见展示、允许摘要融合、参考学习；依据用户指示或已说明的判断 |
| content | 应用的图片、数据、结论或设计/动画方法 |
| planned_use | 正文/附录的页型及用途 |
| final_location | 最终 PPTX 页码、形状 ID/名称或明确文字位置；重排后更新 |
| transformation | 原样、裁切、重绘、摘要、融合、动画迁移等 |
| verification | 尚未使用 / 已放入待核查 / 已在最终文件核查 |
| issue | 文件损坏、重复、冲突、清晰度问题等；无问题留空 |

一份文件可以拆成多条，一条可映射多个目标页。同一观点融合自多个来源时，各来源都要能追踪到实际贡献。

## 核查

- 图片：对照源图与最终画面，确认实际使用且所需细节和标签可见。媒体哈希只能辅助核对，不能判断裁切是否正确。
- 数据/表格：核对数值、单位、分组及最终图表/表格；只把文件名放进来源页不算使用。
- 文字/PDF/对话：逐条确认必讲事实和观点进入正文或附录，摘要没有改变原意。
- 模板参考：记录采用的组件或方法及源页，无需使用库内所有候选。用户指定必用的模板/元素则单独跟踪。
- 备注或来源页：要求可见展示的内容仅出现在这里仍算未覆盖；明确作为背景参考的资料可记录其实际贡献。
- 无法应用的素材：记录具体原因与处理方案，不能以“已检查”代替“已使用”。全部使用任务只在未解决遗漏为零时报告完整覆盖。

最终反馈使用实际核查结果，例如“12 张指定图片均在正文或附录中展示；两份 PDF 的必讲内容已映射到相应页面”。示例数字不可带入真实交付。
